# BF-008 Structured Logging Walkthrough

## Overview
This document summarizes the changes introduced for the BF-008 Structured Logging story. 

A centralized, production-ready structured logging framework was implemented, generating machine-readable JSON logs across the application. It includes proper tracking via `X-Request-ID`, execution duration logging, exception handling, and sensitive data masking.

## Implemented Features

### 1. Centralized Structured Logging (`app.core.logging`)
- **JSON Formatter**: A custom `JSONFormatter` class that formats all logs into a single line of structured JSON with all required fields (e.g. `timestamp`, `level`, `logger`, `module`, `message`).
- **Data Masking**: Automatic scrubbing of sensitive attributes if they accidentally get logged (e.g. `password`, `jwt`, `authorization`).
- **Handler Deduplication**: `setup_logging()` configures the root logger and clears duplicate handlers, specifically preventing default Uvicorn access logs from polluting the output while propagating error logs correctly.

### 2. Context Propagation (`app.core.context`)
- **Context Variables**: Utilizes standard library `contextvars` to define async-safe `request_id` and `user_id` variables.
- These variables are accessed by the `JSONFormatter` to inject tracing IDs into every single log message produced during an HTTP request's lifecycle.

### 3. Middleware Tracing (`app.middleware.logging_middleware`)
- **Logging Middleware**: An ASGI `BaseHTTPMiddleware` was implemented to wrap all HTTP requests.
- **Request ID Handling**: Inspects `X-Request-ID` headers. If missing, it dynamically generates a new UUID. This ID is attached to the response headers automatically.
- **Lifecycle Tracking**: Emits structured `INFO` logs at the beginning (`"Request started"`) and end (`"Request completed"`) of every HTTP request, measuring the `duration_ms` using `time.perf_counter()`.

### 4. Global Exception Handler (`app.api.exceptions`)
- Handles previously unhandled `Exception` crashes globally.
- Ensures the server emits an `ERROR` log including a full stack trace (`exc_info`) without exposing internal implementation details to the client.
- The client receives a clean, standardized `500 Internal Server Error` response.

### 5. Lifespan Integration
- **`app.core.lifespan.py`**: Initializes `setup_logging()` right as the application spins up, enforcing structured JSON formatting before any other initialization tasks occur.

## Testing & Validation
- **Unit Tests (`tests/test_logging.py`)**: Covers ID generation, propagation, formatting, data masking, and exception handling using `anyio` async fixtures. 
- **Compatibility**: Integrated seamlessly with the existing `TestClient` tests and lifespan validation logic. All test suites pass.
